# 商职星途 · 九秩校庆

商职星途是面向山东商业职业技术大学办学 90 周年的学生创作专题网站。项目以“回望校史、走近校友、传承成长”为主线，将学校发展历程、真实校友故事、学习实践材料和个人成长计划整合在同一个网页中。

用户既可以通过校史与校友档案了解母校、寻找榜样，也可以根据自己的兴趣选择成长路线，将启发转化为分阶段的学习任务，并持续记录完成进度。项目希望让校庆纪念与学生的日常学习相连接，让每一步成长成为献礼母校的具体行动。

## 项目定位

- **面向学生的校庆专题**：通过时间轴、人物故事和原创视觉呈现九秩商职的发展与传承。
- **从阅读走向行动**：在校友经历之外提供学习路线、方法卡和实践材料，帮助用户明确下一步。
- **轻量的个人成长工具**：无需注册即可管理计划、收藏校友、记录任务进度，并通过备份迁移个人数据。

适合希望了解学校历史、探索升学与职业方向，或尝试制定学习计划的学生使用。

## 主要功能

### 校庆首页与九秩校史

首页以 1936—2026 年为主题，展示校庆视觉、校史入口、校友故事和成长路线。用户可以从首页选择成长计划，将了解母校、阅读校友故事和完成实践作品纳入自己的行动安排。

校史页面通过时间轴串联学校发展的重要节点，涵盖办学溯源、高职建设与职业本科发展等内容。每个节点保留资料来源和日期，便于继续阅读原文、核对背景。

### 校友风采

校友探索页面支持关键词搜索、分类筛选与收藏。人物详情围绕公开报道整理成长经历、重要阶段与参考资料，帮助用户了解校友在技能竞赛、升学深造和技术就业等方向上的探索。

页面区分人物事实、编辑提炼与学习建议，用户可以收藏感兴趣的校友，在“我的成长”中再次查看相关故事。

### 升学 AI 规划

升学 AI 功能根据用户填写的学历、年级、专业、目标地区、学习基础、目标院校与开始日期等信息，调用 DeepSeek 进行联网检索和计划生成。入口位于“成长传承”的“升学深造”路线，支持指定院校，也支持按地区、专业和历史招生层次等条件推荐院校。

使用流程：

1. 在“成长传承”的升学深造卡片点击“创建学习计划”，或进入路线详情点击“使用这条路线”，填写带“*”的必填项。
2. 在“目标院校与专业”中填写具体学校，或填写“济南本地一本院校，计算机相关专业”等筛选条件；暂未确定学校时也可留空。
3. 点击“检索并生成计划”，查看各项检索任务、已找到的官方资料、带出处的摘要和已用时。未指定院校时，学习行动草稿与检索同时生成。
4. 等待核验与整合完成，在统一预览中检查四阶段任务、建议日期、推荐理由和参考资料；需要调整输入时可返回修改或重新生成。
5. 确认后点击“保存到我的成长”，再按自己的节奏编辑目标与任务、标记进度。预览、返回修改和取消都不会自动创建计划。

未指定具体学校时，当前流程逐校核验三所候选院校，并设计 16 项学习行动。已有生成结果兼容 12—24 项任务。对应年度的正式初试日期未公布时，页面标明“考试季暂定安排”，以暂定学习期限分配任务；正式日期有官方出处时，安排至初试前一天。暂定日期不作为官方考试公告，专科衔接路径和实际报考资格也需要另行核实。

生成等待期间隐藏“使用原始模板”。关闭弹窗、取消或切换页面会停止当前请求。断网、超时或校验失败时不会保存无效计划，失败界面恢复表单和模板入口，保留填写内容及已展示资料供核对；可重试，或使用原始模板建立计划。

生成内容用于辅助规划，摘要未经人工核实。实际报考条件、专业要求、培养地点和考试安排应以对应年份的官方通知为准；“一本/二本”仅指批次取消前的历史招生层次参考，不代表当前硕士招生等级。

### 成长路线与学习实践

项目提供技能竞赛、升学深造和技术就业三类成长路线。路线包含分阶段目标、任务建议与学习资源，可作为创建个人计划的起点，再根据自己的基础和节奏调整。

配套实践内容包括：

| 实践方向 | 主要内容 | 学习目标 |
| --- | --- | --- |
| 校园指南网页 | 使用教学模拟问答练习页面制作、分类与搜索 | 理解网页内容组织与基础交互 |
| 学习记录统计 | 使用 Python 处理模拟学习记录与 CSV 数据 | 练习数据读取、计算与结果核对 |
| 本地服务器 | 运行本地 HTTP 服务并排查访问问题 | 理解文件路径、访问方式与基础排障 |

实践页面提供步骤说明、检查要点和可下载材料。方法卡补充目标拆解、报错排查、官方信息核对、项目说明、作品演示与每周复盘等方法，帮助用户留下可展示、可检验的学习成果。

### 我的成长

用户可以从成长路线创建计划，也可以从空白计划开始，自行设置名称与目标。计划支持添加、编辑和删除任务，为任务设置阶段与目标日期，并手动标记完成状态。

页面展示计划数量、已完成任务、整体完成度与收藏校友数量，便于查看当前积累。每份计划也有独立的进度展示，适合按自己的节奏持续更新。

个人数据支持导出为 JSON 文件。导入时先校验文件内容，再展示确认信息；确认恢复后，备份会替换当前记录，建议先导出现有数据。

## 使用方式

### 直接打开

在浏览器中打开本目录下的 `index.html` 即可使用。网站使用本地样式、脚本和图片，无需安装前端依赖，也没有构建步骤。

校史、校友、成长路线和个人计划等基础功能可在本地使用；升学 AI 生成需要联网，打开外部资料链接也需要网络。

### 本地服务预览

安装 Python 后，在 `project` 目录中运行：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

然后访问 [本地预览](http://127.0.0.1:8765/)，按 `Ctrl+C` 停止服务。

如果当前位于仓库根目录，可改用：

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory project
```

本提交包使用上述Python命令；开发仓库中的tools/dev.js不随提交包提供。上述命令启动的是本机静态预览服务，终端需要保持打开；网站无需构建。

## 技术实现

项目采用原生 HTML、CSS 和 JavaScript，使用单页面结构与 Hash 路由切换内容。页面链接通过 `#/history`、`#/alumni`、`#/paths`、`#/growth` 等路径组织，支持浏览器前进与后退。

JavaScript 使用经典脚本，按 `data → learning → storage → ai-config → ai → app` 的顺序加载，共享功能挂载在 `window.StarPath` 下。资源使用相对路径，兼顾直接打开文件与本地 HTTP 服务两种运行方式。

界面采用响应式布局，兼顾桌面与手机访问，并提供键盘焦点、跳转到主要内容、状态提示等交互支持。个人记录通过 `localStorage` 保存，导入数据与生成结果经过校验，用户输入以转义文本方式呈现。

### AI 并发提速

升学规划需要核对多个主题。若逐项等待检索完成，再让 AI 从全部资料重新组织计划，各环节的等待会依次累积。当前实现通过任务分工、并发调度和提前生成学习行动缩短这条等待链。

- **独立资料并发查找**：指定院校时，国家政策与考试日期、学历资格、专业目录、考试科目、报考限制、培养校区六项任务分别检索。按条件推荐时，政策、资格与候选发现同时推进，找到候选后，再对三所学校分别核验专业与要求、校区与历史层次。每项只处理分配的主题，减少重复检索。
- **共享队列控制并发**：请求由统一调度器管理，最多同时运行 8 个请求；候选发现与逐校核验仍有先后依赖。指定院校至少执行 6 次实际搜索，条件推荐至少 15 次，总上限 18 次；学习行动请求占用并发槽位，但不计搜索次数。取消、超时或失败会停止全部请求。
- **学习行动与检索重叠**：未指定院校时，依据学历、年级、专业和学习基础提前生成 16 项行动，与资料检索同时执行。草稿只设计学习建议，涉及具体院校资格、科目和日期的内容留待核验后调整。
- **缩短最终整合**：各院校任务返回带年度和出处的结构化事实，程序验证并合并院校信息。最后一次 AI 调用只整理标题、目标、摘要及需要修改的行动；阶段、日期和来源网址由程序组装。检索使用 `high` 思考强度，草稿、最终整合或指定院校的计划生成使用 `low`，完成后继续执行完整校验，必要时允许一次最终修复。

未指定院校时的流程可概括为：

```text
表单校验
  ├─ 官方资料检索：政策 / 资格 / 候选发现 → 逐校核验
  └─ 16 项学习行动草稿：与检索共用并发队列
           ↓ 两条分支均完成
核验合并 → 简短整合 → 完整校验 → 预览 → 确认保存
```

两条分支的主要等待时间取决于较慢的一条，再加上后续整合与校验；检索、草稿的重叠部分不能重复相加，实际总用时单独计量。检索通过流式响应及时展示官方来源和带出处摘要，让用户更早看到进展；完整计划通过校验后才统一预览。

**2026-10-09 修正版实测**采用相同模型、输入、检索 `high`、生成 `low`、15/18 次搜索预算与 300 秒超时。条件推荐场景的结果如下：

| 指标 | 优化前 | 修正版 |
| --- | --- | --- |
| 成功率 | 3/3 | 3/3 |
| 完整生成耗时中位数 | 62.30 秒 | 42.92 秒 |
| 并发请求上限 | 6 | 8 |

本轮总耗时中位数下降 **31.1%**，属于并发、结构化核验、学习草稿与最终整合等调整的组合效果，不能单独归因于并发上限从 6 增至 8。修正版还调整了候选线索排序和校区字段提示，并复用首轮三次基线；首版失败样本单独保留。样本量有限且服务时间存在波动，不能保证每次请求达到同样幅度。

流程详见 [升学 AI 流程](docs/education-ai-flow.md)，数据与方法见 [性能说明](docs/ai-performance.md)、[修正版实测报告](docs/reports/ai-overlap-performance/revised/report.md)和[首轮报告](docs/reports/ai-overlap-performance/report.md)。不同优化轮次使用各自基线，提升百分比不能累加。

### 输入缓存优化

先前的请求把考试年份、每轮搜索次数和续查状态等动态内容混入系统提示词前部，容易缩短可重复使用的输入前缀。DeepSeek 会复用已落盘、与后续请求匹配的输入前缀；固定规则放在前部，有助于形成稳定的公共前缀，具体命中由服务端决定，无法保证每次命中。[官方缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)

当前请求组织采用以下方式：

- **固定各类请求的系统规则**：检索、学习行动设计和最终整合各自使用固定提示词，将个人资料、任务定义、搜索次数及续查状态放入结构稳定的用户消息，避免随轮次改写系统规则。
- **保持续接与来源顺序稳定**：接口要求暂停续接时保留原始协议消息；普通补查只发送已有来源和紧凑摘要。最终合并来源按确定顺序排列，避免并发完成顺序改变相同资料的序列化。
- **减少重复输入和输出**：来源表分配 `S1` 等编号，整合时以编号引用，由程序还原原始网址；每项检索只接收所需资料，最终整合使用已核验事实与行动草稿，减少重复叙述和长网址。
- **记录实际用量**：可选的 `onUsage` 回调统计输入命中、未命中及输出 token；流式累计用量按字段合并，避免重复计数。缺失统计标为不可用，用量不写入个人计划或浏览器存储。

缓存复用的是输入处理。每次仍执行联网检索、重新生成和完整校验，不直接复用旧计划或以旧资料代替当轮检索。输入命中率按 `命中输入 token ÷（命中输入 token + 未命中输入 token）` 计算；多请求汇总时先合计 token 再计算比例，不能直接平均各请求百分比，也不能把输出 token 计入分母。

**2026-10-09 的输入缓存对比**使用当时的冻结版本，两类场景各执行优化前后两次，共八轮，全部成功且用量完整；没有额外预热。两轮合计结果为：

| 场景 | 输入加权命中率变化 | 未命中输入变化 |
| --- | --- | --- |
| 指定院校 | 22.23% → 38.89% | 75,696 → 59,538 token |

## 数据保存与网络使用

- 收藏与已保存的成长计划由当前浏览器管理，项目没有账号系统或云端同步功能。
- 清理浏览器数据、使用隐私模式、更换浏览器或移动网页文件，可能影响记录的保存与读取。
- 浏览器无法使用持久化存储时，页面会提示用户导出备份，避免关闭页面后丢失本次记录。
- 使用升学 AI 时，填写的个人情况会发送给 DeepSeek，用于检索与生成建议。
- 练习材料保存在本地；Python 实践需要本地 Python 环境，首次安装工具可能需要联网。

### 备份与恢复

1. 在“我的成长”点击“导出备份”，保存 JSON 文件。备份包含计划、任务、完成状态、校友收藏，以及已保存 AI 计划的参考资料、日期状态等信息。
2. 更换环境前先备份。直接文件、`http://127.0.0.1:8765/`、其他端口或其他浏览器的记录不会自动同步；`localhost` 和 `127.0.0.1` 也属于不同地址。
3. 在目标环境点击“导入备份”，选择本项目导出的 JSON 文件。系统先校验格式、版本、记录和日期，再展示计划、任务及收藏数量供确认。
4. 确认恢复会替换当前全部记录，不与现有记录合并；已有内容需要保留时先导出。格式错误或取消确认不会改变当前记录。

当前支持最多 20 份计划、每份最多 100 项任务，备份文件不超过 32 MiB（按 UTF-8 字节计算）。浏览器无法持久保存或恢复写入时发现其他页面已更新记录，当前修改仅在本次打开期间有效，应及时导出；发现旧记录损坏时，可先下载原始记录，再处理恢复。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 打开后没有页面内容 | 使用支持 JavaScript 的浏览器，确认未禁用脚本，并检查 `js/` 和 `css/` 是否随 `index.html` 一起保留 |
| 图片或实践下载打不开 | 完整保留 `project` 目录结构；HTTP 预览应服务 `project/`，核对资源相对路径和文件名 |
| 换浏览器或启动服务后计划不见了 | 返回原来的浏览器及地址导出备份，再到新环境导入；不同地址的存储独立 |
| 页面提示无法长期保存 | 检查浏览器存储权限或隐私模式，先导出当前记录；当前会话记录不能保证关闭后保留 |
| 导入失败 | 使用本项目导出的完整 JSON，检查 32 MiB 限制与错误提示；不要改写版本或记录编号，校验失败时现有数据保留 |
| AI 生成失败或等待较长 | 查看具体错误、任务进度和已找到资料；确认网络及 AI 服务配置可用，适当缩小目标后重试，也可使用原始模板 |
| 推荐资料年份与目标年份不同 | 未来年度通知可能尚未公布，先核对资料适用年度和待核实提示；不能将旧要求或暂定日期视为未来年度正式通知 |
| Python 命令不可用 | 检查 Python 安装，Windows 可尝试 `py --version` 并替换后续命令中的 `python` |
| 预览端口被占用 | 将启动命令中的 8765 改为其他可用端口，并同步修改访问地址；新端口的浏览器记录独立，迁移前先备份 |
